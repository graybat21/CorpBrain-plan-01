# **B+C+D 융합 모델 – 최종 Top 5 KSFs (Final Version)**

## 1. **Zero-Effort 데이터 수집의 완전 자동화 (Zero-Effort Ingestion as Table Stakes)**

**핵심 정의**
사용자의 문서 작성·정리 행동을 요구하지 않고, 모든 지식을 **백그라운드에서 자동 수집**하는 능력

**선정 근거**
소규모 조직은 문서를 작성할 리소스 자체가 없으며, 기존 솔루션의 실패 원인은 “사용자가 입력해야 한다”는 전제에 있음.
따라서 **Zero-Effort는 차별화 요소가 아니라 시장 진입 최소 조건(Table Stakes)**이다.

**전략적 보완 (A 반영)**

* 단순 API 연동이 아니라 **“작성자 없는 조직 지식 생성 구조”**를 목표로 설계
* 콜드 스타트 문제를 제품이 아니라 **파이프라인으로 해결**

**실행 포인트**

* 카카오톡 / Slack / 이메일 / 협업툴 ingestion pipeline 구축
* 이벤트 기반 자동 수집 + 실시간 파싱 구조
* 데이터 누락률 최소화 (coverage KPI 설정)

---

## 2. **자율 지식 구조화 엔진 기반 지식 가드닝 (Autonomous Knowledge Gardening as Core Moat)**

**핵심 정의**
수집된 데이터를 AI가 스스로 구조화·연결·정리하는 **강화학습 기반 자율 관리 시스템**

**선정 근거**
데이터 수집은 누구나 가능하지만,
**“지식을 usable한 구조로 만드는 능력”이 진짜 해자(Moat)**

**전략적 보완 (A 반영)**

* Notion식 수동 편집 모델을 완전히 폐기
* **“지식 정리는 인간이 아니라 시스템이 한다”는 패러다임 전환**
* SI 인력 투입 영역을 **RL 기반 소프트웨어로 치환**

**실행 포인트**

* 문서 간 관계 추론 (linking / clustering)
* 자동 taxonomy 재구성
* 사용자 피드백 → reward function 반영 구조

---

## 3. **온프레미스 어플라이언스 렌탈을 통한 보안 장벽 제거 (Security-driven Hardware-as-a-Service)**

**핵심 정의**
데이터 유출에 대한 근본적 불안을 제거하기 위해,
**사내망에서만 동작하는 온프레미스 환경을 월 렌탈 형태로 제공**

**선정 근거**
타겟 고객의 구매 결정은 기능이 아니라
**“우리 데이터가 외부로 나가는가?”라는 본질적 불안 해소 여부**에 의해 결정됨

**전략적 보완 (A 반영)**

* 단순 온프레미스 제공이 아니라
  **“보안을 제품의 핵심 가치로 전환”**
* 초기 CAPEX 문제를 해결하기 위해
  **렌탈 금융 구조 + 하드웨어 파트너십 필수**

**실행 포인트**

* 워크스테이션 기반 온프레미스 패키지 설계
* 월 구독형 과금 모델
* 설치/운영 자동화 (Plug & Play 수준)

---

## 4. **문서 충돌 제어 UX와 피드백 루프 기반 자기 진화 시스템 (Self-Improving Feedback Loop UX)**

**핵심 정의**
자동 수집 구조에서 발생하는 중복·충돌을
사용자의 최소 개입으로 해결하면서,
그 행동이 곧 AI 성능 향상으로 이어지는 구조

**선정 근거**
멀티 채널 ingestion 환경에서는
충돌과 중복이 필연적이며, 이를 해결하지 못하면 시스템 신뢰도가 붕괴됨

**전략적 보완 (A 반영)**

* 단순 UI 문제가 아니라
  **“사용자 행동을 학습 신호로 전환하는 시스템 설계 문제”**
* UX = RL 성능 향상 엔진

**실행 포인트**

* 직관적 승인/병합/삭제 인터페이스
* 사용자 액션 → 즉시 모델 반영
* 충돌 처리 시간 최소화 KPI

---

## 5. **비핵심 기술의 전략적 외부 조달과 R&D 집중 (Strategic Focus & Buy-over-Build)**

**핵심 정의**
전처리·파싱·기초 RAG 등은 외부에서 조달하고,
핵심 경쟁력에 모든 리소스를 집중

**선정 근거**
스타트업이 모든 스택을 직접 개발하는 순간
속도와 자원에서 패배가 확정됨

**전략적 보완 (A 반영)**

* “무엇을 잘할 것인가”보다
  **“무엇을 절대 하지 않을 것인가”를 명확히 정의**
* 핵심 집중 영역:
  → 자율 가드닝
  → 지식 구조화
  → 사용자 피드백 루프

**실행 포인트**

* OCR / 파서 / 임베딩 등 외부 솔루션 활용
* 내부 개발 영역 명확히 제한
* R&D 투자 비율 강제 설정 (Core 집중)

# **최종 요약 (One-line KSF Set)**

이 모델의 성공은 결국 아래 5가지에 달려 있습니다:

1. **입력 없이도 데이터가 쌓이는가 (Zero-Effort Ingestion)**
2. **쌓인 데이터가 자동으로 정리되는가 (Autonomous Structuring)**
3. **보안 불안을 원천 차단했는가 (On-Prem HaaS)**
4. **사용자 행동이 곧 성능 개선으로 이어지는가 (Feedback Loop)**
5. **리소스를 핵심에만 집중하고 있는가 (Strategic Focus)**
