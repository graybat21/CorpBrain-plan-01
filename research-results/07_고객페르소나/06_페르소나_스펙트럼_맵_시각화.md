# **CorpBrain Persona Spectrum Map (페르소나 시각화 맵)**

지금까지 도출된 고객 페르소나(이수아, 강서연, 한유리, 임성진) 간의 관계와 시장 내 위치, 제품과의 접점을 명확히 구조화하기 위해 **5가지 관점의 시각화 맵(Mermaid)**을 구성했습니다.

---

## **Map 1. 스펙트럼 전체 구조 (Spectrum Overall Structure)**
각 페르소나가 CorpBrain 비즈니스 내에서 어떤 역할을 담당하며 어떻게 상호작용하는지를 보여주는 전체 구조도입니다.

```mermaid
graph TD

    classDef adjacent fill:#E8F5E9,stroke:#388E3C,stroke-width:2px
    classDef extreme fill:#FCE4EC,stroke:#C2185B,stroke-width:2px
    classDef nonuser fill:#EEEEEE,stroke:#616161,stroke-width:2px

    Root((CorpBrain<br>Business))

    Root --> Ext[극단 사용자<br>성능 한계점]:::extreme
    Root --> Non[비활성 사용자<br>인프라 전환점]:::nonuser

    Core --> C1["**이수아 (29, PM)**<br>Zero-UI 문서화 체감<br>초안 승인율 80% 주도"]:::core

    Ext --> E1["**한유리 (35, 에이전시)**<br>10개 툴 동시 접속<br>시맨틱 병합 스트레스 테스트"]:::extreme
    Non --> N1["**임성진 (46, CISO)**<br>SaaS 도입 원천 배제<br>On-Premise 모델 근거"]:::nonuser

    A1 -. "도입 승인 후<br>실무 사용" .-> C1
    C1 -. "엔진 한계<br>돌파 테스트" .-> E1
    E1 -. "엔터프라이즈급<br>신뢰도 확보 시" .-> N1
```

## **Map 2. 시장 세그먼트 매트릭스 (Market Segment Quadrant)**
TAM-SAM-SOM 산출 시 정의했던 '파편화 고통'과 '결제 의향/보안 유연성'을 축으로 4명의 페르소나 위치를 맵핑했습니다.

```mermaid
quadrantChart
    title CorpBrain 시장 세그먼트 페르소나 매트릭스
    x-axis "보안 엄격 / 예산 부족 (Low WTP)" --> "보안 유연 / 자체 예산 (High WTP)"
    y-axis "단일 툴 의존 (Low Pain)" --> "다중 툴 파편화 (High Pain)"
    quadrant-1 "Q1: Tech-Savvy (최우선 타겟)"
    quadrant-2 "Q2: Pragmatic (조건부 타겟)"
    quadrant-3 "Q4: Status-Quo (비활성/망분리)"
    quadrant-4 "Q3: 관심 부족형 (보류 타겟)"
    
    "C1 이수아 (Core)": [0.85, 0.85]
    "E1 한유리 (Extreme)": [0.70, 0.98]
    "A1 강서연 (Adjacent)": [0.35, 0.75]
    "N1 임성진 (Non-user)": [0.10, 0.20]
```
- **해석:** 이수아(우상단)가 가장 이상적인 수익원이지만, 실제 B2B 시장의 파이를 키우려면 예산/보안 장벽에 막혀있는 강서연(좌상단)을 Q1 영역으로 끌어와야(마스킹, 바우처 등) 합니다. 임성진은 현재의 SaaS 모델로는 절대 도달할 수 없는 좌하단에 위치합니다.

실제 기업에 CorpBrain 솔루션이 안착하고 확장되는 과정에서 각 페르소나가 어떤 흐름으로 엮이는지 보여줍니다.

    Ent -.-> N1["**임성진 (규제 시장)**<br>On-Premise 패키지 제안"]:::expansion

## **Map 4. 플랫폼 접점 모델 (Platform Touchpoint Model)**
페르소나들이 CorpBrain 제품의 **어떤 계층(Layer)의 피처(Feature)**와 직접적으로 상호작용하는지 아키텍처 관점에서 시각화했습니다.

```mermaid
graph TD
    classDef persona fill:#FFFFFF,stroke:#333,stroke-width:2px,stroke-dasharray: 5 5

    subgraph "데이터 입력 계층 (Zero-UI)"
        E1(("한유리<br>(10개 툴)")):::persona -. "API 백그라운드 연동" .-> Collector[데이터 수집기]
        C1(("이수아<br>(3개 툴)")):::persona -. "API 백그라운드 연동" .-> Collector
    end

    subgraph "엔진 및 보안 계층 (Engine & Security)"
        Collector --> Semantic[시맨틱 융합 엔진<br>Context Collision 해결]
        Semantic --> Masking[기밀/주민번호 마스킹<br>데이터 난독화]
    end

    subgraph "출력 및 통제 계층 (Output & Control)"
        Semantic --> HITL[HITL 승인 대시보드<br>1클릭 초안 확정]
        Masking --> RBAC[역할 기반 권한 통제<br>부서간 사일로 보호]
        
        HITL ==> C1
        RBAC ==> A1(("강서연<br>(보안 통제)")):::persona
    end

    subgraph "독립 인프라 계층 (Infra)"
        N1(("임성진<br>(망분리 통제)")):::persona x-- "SaaS 접근 차단" --x Collector
        N1 -. "VPC 컨테이너 배포" .-> OnPrem[고객사 자체 클라우드<br>BYOC / On-Premise]
    end
```

## **Map 5. 제품 설계 우선순위 (Product Design Priority)**
MVP(최소 기능 제품) 개발 시 리소스를 어디에 집중해야 하는지, 페르소나별 비중을 나타냅니다.

```mermaid
pie title "Phase 1 MVP 개발 리소스 분배 (우선순위)"
    "Zero-UI 수집 엔진 (이수아/한유리 타겟)" : 45
    "시맨틱 초안 병합 및 HITL (이수아 타겟)" : 30
    "보안 마스킹 및 RBAC (강서연 타겟)" : 20
    "On-Premise 아키텍처 R&D (임성진 타겟)" : 5
```

### **우선순위 해석:**
1. **45% (Zero-UI 엔진):** 사용자가 직접 입력하는 마찰을 없애는 것이 핵심이자, E1(한유리)의 극한 환경까지 버텨야 하므로 가장 많은 엔지니어링 리소스가 투입됩니다.
2. **30% (HITL 및 병합):** 이수아(C1)가 심리적 통제감을 느끼며 초안을 승인할 수 있는 대시보드 개발에 집중합니다.
3. **20% (보안 및 마스킹):** 강서연(A1)을 설득하기 위한 최소한의 B2B 세일즈 무기(Table Stakes)를 구축합니다.
4. **5% (On-Premise 준비):** 당장 개발하지는 않으나, 임성진(N1)의 요구사항을 아키텍처 초기 설계(모듈화 등)에 반영해 두어 훗날 기술 부채를 방지합니다.
