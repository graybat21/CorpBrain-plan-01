# CorpBrain: 중소기업 지식 위키화 에이전트

> Andre Karpathy의 LLM-Wiki 패턴과 P-Reinforce 강화학습 구조화 로직을 결합하여,
> 중소기업의 파편화된 문서·지식을 자동으로 수집·분류·위키화하는 AI 에이전트 시스템.

---

## 📌 배경 및 문제 정의

중소기업은 대기업과 달리 지식 관리 체계가 부재한 경우가 대부분이다.

| 문제 | 현실 |
|------|------|
| **저장소 파편화** | Google Drive, NAS, Dropbox, 로컬 PC 등에 문서가 산재 |
| **직원별 사일로** | 핵심 노하우가 개인 머릿속·개인 폴더에만 존재 |
| **문서 형식 비표준** | HWP, DOCX, PDF, PPT, 이메일, 메신저 대화 등 혼재 |
| **인수인계 실패** | 퇴사 시 지식 유실, 신입 온보딩 비용 증가 |
| **검색 불가** | 어떤 문서가 어디에 있는지 아무도 모름 |

**CorpBrain**은 이 파편들을 자동으로 수집하고, LLM이 읽고 이해하여 **영속적 기업 위키**로 컴파일하는 시스템이다.

---

## 🏗️ 아키텍처: 4계층 구조

Karpathy의 3계층(Raw → Wiki → Schema)에 **수집 계층(Connector Layer)**을 추가한다.

```
┌─────────────────────────────────────────────────┐
│  Layer 0: Connectors (수집 계층)                 │
│  Google Drive · NAS · Dropbox · Email · Slack    │
│  → 자동 크롤링 & 변환 → 00_Raw/로 통합           │
├─────────────────────────────────────────────────┤
│  Layer 1: Raw Sources (원본 보관소)              │
│  불변 원본 저장, 출처·날짜·부서 메타데이터 태깅     │
├─────────────────────────────────────────────────┤
│  Layer 2: Corp Wiki (기업 위키)                  │
│  LLM이 생성·유지하는 마크다운 위키                 │
│  부서별·프로젝트별·주제별 구조화된 지식             │
├─────────────────────────────────────────────────┤
│  Layer 3: Schema & Policy (스키마 & 정책)        │
│  위키 운영 규칙, RL 분류 정책, 부서별 가중치       │
└─────────────────────────────────────────────────┘
```

## 🧠 강화학습 기반 구조화 로직

P-Reinforce의 RL 로직을 기업 환경에 맞게 확장한다.

### 보상 함수

$$R = w_1(\text{Categorization Accuracy}) + w_2(\text{Graph Connectivity}) + w_3(\text{Department Relevance}) + w_4(\text{User Satisfaction}) + w_5(\text{Freshness})$$

| 가중치 | 설명 | 기업 컨텍스트 |
|--------|------|---------------|
| $w_1$ | 분류 정확도 | 올바른 부서·프로젝트에 배치되었는가 |
| $w_2$ | 그래프 연결성 | 관련 문서 간 링크가 충분한가 |
| $w_3$ | 부서 적합도 | 해당 부서 담당자가 활용하는가 |
| $w_4$ | 사용자 만족도 | 수정/이동/피드백 반영 |
| $w_5$ | 최신성 | 최신 정보가 우선 반영되는가 |

### 상태-행동-보상 사이클

```
State (상태 분석)
├── 현재 10_Wiki/ 폴더 트리 스캔
├── 20_Meta/Graph.json 지식 지형도 파악
├── 부서별 문서 분포 분석
└── 최근 피드백 이력 로드

Action (행동)
├── 기존 분류: 유사도 ≥ 85% → 기존 폴더 배치
├── 신규 폴더 생성: 새 주제 등장 시 상위 개념 도출
├── 구조 리팩터링: 폴더 내 문서 > 15개 시 세분화
├── 교차 부서 링크: 관련 부서 문서 간 자동 연결
├── 충돌 감지: 기존 문서와 모순되는 내용 플래그
└── 용어 통일: 사내 용어 사전(Glossary) 기준 정규화

Reward (보상)
├── 명시적: 담당자 승인/수정/거부 피드백
├── 암묵적: 문서 조회수, 링크 클릭, 재사용 빈도
└── 정책 업데이트 → 20_Meta/Policy.md 갱신
```

## 🔌 커넥터 (데이터 수집 파이프라인)

파편화된 소스를 자동으로 수집하여 `00_Raw/`로 통합한다.

| 커넥터 | 수집 방법 | 변환 |
|--------|----------|------|
| **Google Drive** | Drive API (OAuth2), 공유 드라이브 포함 | DOCX/PPT → MD |
| **NAS** | SMB/NFS 마운트, inotify 감지 | 파일 복사 + 메타데이터 추출 |
| **Dropbox** | Dropbox API, 웹훅 알림 | 파일 동기화 |
| **Email** | IMAP/Gmail API | EML → MD (첨부파일 분리 보관) |
| **Slack/메신저** | Slack API / 카카오워크 API | 채널별 대화 → 스레드 단위 MD |
| **HWP** | hwp5txt / LibreOffice 변환 | HWP → MD or TXT |
| **PDF** | PyMuPDF / OCR(Tesseract) | PDF → MD (이미지 포함 시 OCR) |
| **수동 업로드** | 웹 UI 또는 CLI | 원본 보존 + MD 변환 |

### 수집 플로우

```
[외부 저장소] → Connector → 포맷 변환(→MD) → 메타데이터 태깅 → 00_Raw/{source}/{date}/
                                                    ↓
                                            중복 검사 (해시 비교)
                                                    ↓
                                            Ingest Queue → LLM 처리
```

## 📝 위키 문서 템플릿

LLM이 생성하는 모든 위키 문서의 표준 형식이다.

```markdown
---
id: {{UUID}}
category: "[[10_Wiki/Path/To/Folder]]"
department: "마케팅팀"          # 주 담당 부서
contributors: ["김철수", "박영희"]  # 관련 담당자
confidence_score: 0.0 ~ 1.0    # RL 기반 확신도
sensitivity: "internal"         # public | internal | confidential
source_type: "회의록"           # 기획서 | 회의록 | 보고서 | 매뉴얼 | 메신저 | 이메일
tags: [tag1, tag2]
created: 2026-04-24
last_reinforced: 2026-04-24
source_refs: ["00_Raw/google-drive/2026-04-20/marketing_report.md"]
---

# [[문서 제목]]

## 📌 한 줄 요약
> 이 문서의 핵심을 꿰뚫는 단 한 문장.

## 📖 구조화된 내용
- **핵심 사항:** (문서에서 추출한 가장 중요한 포인트)
- **세부 내용:** (불렛포인트 위주의 간결한 정리)
- **액션 아이템:** (후속 조치가 필요한 항목)

## 👥 관련 부서 및 담당자
- **주관 부서:** [[Departments/마케팅팀]]
- **협조 부서:** [[Departments/개발팀]]

## ⚠️ 모순 및 업데이트
- **기존 문서와의 충돌:** [[이전_문서]]와 달라진 점 기록
- **버전 변경 사항:** 정책/수치 변경 이력

## 🔗 지식 연결
- **상위:** [[상위_카테고리]]
- **관련:** [[연관_문서_A]], [[연관_문서_B]]
```

## ⚙️ 에이전트 오퍼레이션

Karpathy의 Ingest-Query-Lint 패턴을 기업 환경에 확장한다.

### 1. Ingest (수집·위키화)

```
트리거: 커넥터가 00_Raw/에 새 파일 감지
    ↓
LLM이 원본 읽기 + 기존 위키 컨텍스트 로드
    ↓
RL 정책에 따라 분류 (부서·프로젝트·주제)
    ↓
위키 문서 생성 또는 기존 문서 업데이트
    ↓
관련 문서 간 [[쌍방향 링크]] 설정
    ↓
20_Meta/Index.md, Graph.json, Log.md 갱신
    ↓
Git 커밋: "[CorpBrain] ingest: {부서}/{문서제목} 위키화 완료"
    ↓
담당 부서에 알림 (Slack/이메일)
```

### 2. Query (질의·탐색)

```
사용자 질문 입력
    ↓
20_Meta/Index.md에서 관련 페이지 탐색
    ↓
해당 위키 페이지 읽기 + 필요 시 원본 참조
    ↓
답변 생성 (출처 명시)
    ↓
(선택) 유용한 답변 → 새 위키 페이지로 저장
```

### 3. Lint (건강성 검사)

주기적으로(주 1회 권장) 위키 전체 점검:

- **모순 검출**: 서로 다른 문서에서 상충하는 정보
- **고아 페이지**: 아무 링크도 없는 고립된 문서
- **오래된 정보**: 6개월 이상 갱신되지 않은 문서 플래그
- **누락 페이지**: 링크는 있으나 실제 문서가 없는 항목
- **용어 불일치**: Glossary 기준 비표준 용어 사용 감지
- **부서 커버리지**: 특정 부서의 문서가 부족한 영역 식별

### 4. Digest (요약 리포트) — 기업 전용 추가 오퍼레이션

```
주간/월간 자동 리포트 생성:
- 이번 주 추가된 지식 요약
- 부서별 지식 기여도
- 가장 많이 조회/활용된 문서 Top 10
- 발견된 지식 갭(gap) 보고
- RL 정책 변화 요약
```

## 🔐 보안 및 접근 제어

기업 문서는 개인 지식과 달리 **접근 권한 관리**가 필수적이다.

```yaml
# 30_Access/permissions.yaml 예시
roles:
  admin:
    read: ["*"]
    write: ["*"]
  department_lead:
    read: ["10_Wiki/**", "20_Meta/Index.md"]
    write: ["10_Wiki/{own_department}/**"]
  employee:
    read: ["10_Wiki/{own_department}/**", "10_Wiki/Policies/**"]
    write: []

sensitivity_levels:
  public: "전사 공개"
  internal: "사내 한정"
  confidential: "해당 부서 + 경영진만 열람"
```

## 💡 기업 담당자 가이드: "에이전트를 어떻게 훈련시킬 것인가?"

CorpBrain 에이전트는 **사용자 피드백으로 학습**한다.

| 피드백 유형 | 예시 | 에이전트 반응 |
|-------------|------|---------------|
| **승인** | "이 분류 정확해요" | 해당 분류 패턴의 가중치 증가 |
| **수정** | "이건 '마케팅'이 아니라 '영업' 문서예요" | 두 부서 간 경계선 재조정 |
| **병합** | "이 두 문서는 같은 내용이에요" | 중복 감지 정책 강화 |
| **분리** | "이 문서는 두 주제를 다루고 있어요" | 문서 분할 패턴 학습 |
| **기밀 지정** | "이 내용은 경영진만 봐야 해요" | sensitivity 분류 정책 업데이트 |
| **방치** | 위키를 그대로 사용 | 암묵적 승인으로 정책 고착 |

## 📋 스키마 파일 (AGENTS.md) 핵심 지침

```markdown
# Role: CorpBrain Agent (기업 지식의 정원사)

당신은 중소기업의 파편화된 지식을 영속적 위키로 변환하는 CorpBrain 엔진이다.
```
